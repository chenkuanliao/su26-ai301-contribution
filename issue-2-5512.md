## Problem Summary

This Flax issue reports that `flax.nnx.cond` (and the closely related `flax.nnx.switch`) causes JAX **tracing cache misses**, which in turn prevents JAX's persistent compilation cache from loading. Every call to `nnx.cond` wraps the user's `true_fun`/`false_fun` in a freshly constructed `SimpleCondFn` instance before handing them to `jax.lax.cond`. Because a brand-new wrapper object is created on every call, each wrapper has a distinct Python object identity, so JAX's tracing cache — which keys on the identity of the callable it traces — never recognizes the function it has already seen.

JAX surfaces this as a `TRACING CACHE MISS` warning:

```
never seen function: true_fn id=... defined at .../repro_cond_miss.py:15
but seen another function defined on the same line; maybe the function is
being re-defined repeatedly, preventing caching?
```

The practical impact is that modules using `nnx.cond` re-trace (and can re-compile) on every invocation instead of hitting the cache. For large modules with long compilation times, this is a significant, repeated performance cost.

The issue author includes a self-contained reproduction that both demonstrates the cache misses and validates a fix: caching the `SimpleCondFn` wrapper instances in a `WeakKeyDictionary` keyed by `(function, graph)` so the same wrapper is reused across calls, restoring cache hits.

## Phase II: Understanding, Reproduction, and Solution Approach

### Understanding the Issue

#### Problem Description

`nnx.cond` is Flax NNX's wrapper around `jax.lax.cond`. It exists so that the branch functions (`true_fun`/`false_fun`) can read and write NNX `Variable`/`Module` state while still being traced as pure functions by JAX. To do that, when running in the tree-mode / no-graph-updates path, it wraps each branch in a small adapter object, `SimpleCondFn`, that snapshots NNX state, calls the user function, and returns `(out, updates)`:

```python
out, updates = jax.lax.cond(
    pred,
    SimpleCondFn(true_fun, graph=graph),
    SimpleCondFn(false_fun, graph=graph),
    *operands,
)
```
(`flax/nnx/transforms/transforms.py:623`)

The problem is that `SimpleCondFn(true_fun, graph=graph)` constructs a **new object every single time `nnx.cond` is called**. JAX's tracing cache keys on the identity of the callable passed to `lax.cond`. Two `SimpleCondFn` instances that wrap the *same* `true_fun` with the *same* `graph` flag are semantically identical, but because they are distinct Python objects with different `id()`s, JAX treats them as different functions and re-traces from scratch. `SimpleCondFn` is even declared `@dataclasses.dataclass(eq=False)`, so it uses default identity-based equality/hashing — two equal-content instances are never considered equal.

`switch` has the exact same pattern (`transforms.py:680`), building a fresh `SimpleCondFn` per branch on every call.

#### Expected Behavior

Repeated calls to `nnx.cond` (or `nnx.switch`) with the same branch functions should hit JAX's tracing cache, so the function is traced once and subsequent calls reuse the cached jaxpr / compiled executable. The NNX wrapper should not defeat caching that the user would get from calling `jax.lax.cond` directly.

#### Current Behavior

Every call constructs new `SimpleCondFn` wrappers with fresh object identities, so JAX logs a `TRACING CACHE MISS` for each branch on each call and re-traces. With `jax_explain_cache_misses` enabled, the warning explicitly points at `transforms.py:623` and says the function appears to be "re-defined repeatedly, preventing caching." This also blocks JAX's *persistent* compilation cache from loading, so the cost is paid even across processes/runs.

#### Affected Components

- `flax/nnx/transforms/transforms.py`
  - `cond` (`transforms.py:588`) — constructs `SimpleCondFn(true_fun, ...)` / `SimpleCondFn(false_fun, ...)` inline at the `jax.lax.cond` call (`transforms.py:623`–`626`).
  - `switch` (`transforms.py:646`) — builds `[SimpleCondFn(f, graph=graph) for f in branches]` at the `jax.lax.switch` call (`transforms.py:680`).
  - `SimpleCondFn` (`transforms.py:565`) — `@dataclasses.dataclass(eq=False)`; identity-based, so freshly created instances never compare equal even when wrapping identical `(f, graph)`.

> Note: this only affects the tree-mode / `graph_updates=False` path that actually calls `jax.lax.cond` with `SimpleCondFn`. The full graph-mode path (`_cond` with `split_inputs`/`merge_inputs`) goes through a different mechanism.

#### Steps to Reproduce

2. Define two module-level branch functions, `true_fn`/`false_fn` (stable `id()`s for the whole run).

4. Observe a `TRACING CACHE MISS` for both branches on **every** iteration, pointing at `transforms.py:623`.
5. Monkeypatch `SimpleCondFn` with a `WeakKeyDictionary`-cached factory keyed by `(f, graph)` and re-run; observe "Cache MISS" only on the first iteration and "Cache HIT" (reused `wrapper_id`) thereafter.

Reproduction script used (`repro/issue_5512.py`, adapted from the issue author's script):

```python
import weakref
from flax import nnx
from flax.nnx.transforms import transforms as nnx_transforms
import jax

jax.config.update("jax_log_compiles", True)
jax.config.update("jax_explain_cache_misses", True)

def true_fn(x):
    return x + 1.0

def false_fn(x):
    return x - 1.0

original_SimpleCondFn = nnx_transforms.SimpleCondFn

def run_test(name, patch_fn):
    print(f"\n--- Running Test: {name} ---", flush=True)
    patch_fn()
    def test_fn(pred, x):
        # graph_updates=False forces the SimpleCondFn path
        return nnx.cond(pred, true_fn, false_fn, x, graph_updates=False)
    for i in range(3):
        print(f"\nIteration {i}:", flush=True)
        pred = jax.numpy.array(i % 2 == 0)
        jax.block_until_ready(test_fn(pred, 1.0))

# Original behavior: new wrapper per call
def apply_buggy_patch():
    def factory(f, graph):
        inst = original_SimpleCondFn(f, graph)
        print(f"  [BUGGY] new wrapper for {f.__name__}: wrapper_id={id(inst)}", flush=True)
        return inst
    nnx_transforms.SimpleCondFn = factory

# Fix: cache wrappers by (f, graph) using weak refs
_cache = weakref.WeakKeyDictionary()
def apply_patched_patch():
    _cache.clear()
    def factory(f, graph):
        if f not in _cache:
            _cache[f] = {}
        if graph not in _cache[f]:
            _cache[f][graph] = original_SimpleCondFn(f, graph)
            print(f"  [PATCHED] Cache MISS for {f.__name__}: wrapper_id={id(_cache[f][graph])}", flush=True)
        else:
            print(f"  [PATCHED] Cache HIT for {f.__name__}: wrapper_id={id(_cache[f][graph])}", flush=True)
        return _cache[f][graph]
    nnx_transforms.SimpleCondFn = factory

run_test("BUGGY (Original)", apply_buggy_patch)
run_test("PATCHED", apply_patched_patch)
```

- **My findings:**
  - The bug reproduces directly on current `main` — there is no "works by accident on newer backends" caveat like contribution #1 had. This is a live issue today.
  - The root cause is purely Python object identity: `jax.lax.cond` caches on the identity of the callable, and `nnx.cond` hands it a fresh `SimpleCondFn` each call. The branch user functions (`true_fn`/`false_fn`) keep stable `id()`s; only the wrapper churns.
  - The reporter's `WeakKeyDictionary` approach is the right shape: key on the *user function* (weakly, so we don't keep dead functions alive) and then on the `graph` bool, and reuse the wrapper. Weak keys matter because locally-defined branch functions should be collectable once they go out of scope.
  - `switch` shares the identical pattern and should get the same treatment for consistency.

### Solution Approach

#### Analysis

The fix must guarantee that, given the same `(f, graph)`, `nnx.cond`/`nnx.switch` pass the *same* `SimpleCondFn` object to `jax.lax.cond`/`switch` so JAX's tracing cache recognizes it. Two design points:

1. **Key:** `(f, graph)`. `graph` is a `bool`, so the natural structure is a `WeakKeyDictionary` keyed by `f` whose value is a small dict keyed by `graph` (this is exactly what the reporter prototyped).
2. **Weakness:** the function `f` must be a *weak* key. If we held a strong reference, every branch function ever passed to `nnx.cond` would be kept alive forever — a memory leak, especially for closures/lambdas created per-call. `WeakKeyDictionary` lets the wrapper be collected once the user function is gone. (`SimpleCondFn` keeps a strong ref to `f`, but only for as long as the wrapper itself is reachable from the cache value, which is fine.)

#### Proposed Solution

Introduce a module-level cache and a helper that returns a memoized `SimpleCondFn`, then use it in both `cond` and `switch`:

```python
_simple_cond_fn_cache: tp.MutableMapping = weakref.WeakKeyDictionary()

def _get_simple_cond_fn(f, graph: bool) -> SimpleCondFn:
    by_graph = _simple_cond_fn_cache.get(f)
    if by_graph is None:
        by_graph = {}
        _simple_cond_fn_cache[f] = by_graph
    wrapper = by_graph.get(graph)
    if wrapper is None:
        wrapper = SimpleCondFn(f, graph=graph)
        by_graph[graph] = wrapper
    return wrapper
```

Then replace the inline constructions:

- `cond` (`transforms.py:625`–`626`): `SimpleCondFn(true_fun, graph=graph)` → `_get_simple_cond_fn(true_fun, graph)` (same for `false_fun`).
- `switch` (`transforms.py:680`): `[SimpleCondFn(f, graph=graph) for f in branches]` → `[_get_simple_cond_fn(f, graph) for f in branches]`.

This is a behavior-preserving change: `SimpleCondFn`'s `__call__` is pure with respect to the instance (it captures only `f` and `graph`), so reusing an instance across calls is safe. The only observable difference is that JAX now sees a stable callable identity and hits its tracing cache.

> **Edge case (resolved in Phase III):** a `WeakKeyDictionary` requires `f` to be weak-referenceable. I initially worried about `functools.partial`, but on testing (CPython 3.12) plain functions, lambdas, *and* `functools.partial` are all weak-referenceable — the realistic non-weak-referenceable case is a callable instance whose class uses `__slots__` without `__weakref__`. The implementation wraps the cache lookup in `try/except TypeError` and falls back to constructing a fresh `SimpleCondFn` for any non-weak-referenceable callable, so it can never crash.

Then add a regression test that asserts wrapper identity is stable across calls (and, ideally, that no `TRACING CACHE MISS` is emitted on the second call).

## Phase III: Testing Strategy and Implementation Notes

> **Pull request:** https://github.com/google/flax/pull/5518 — "Fix nnx.cond tracing cache misses by caching SimpleCondFn wrappers" (open). The notes below describe the change exactly as submitted.

### Scope Decision

This is a live bug on current `main` (flax 0.12.7 / jax 0.10.1), so unlike contribution #1 the contribution is a real fix plus regression tests, not test-only hardening. The fix is intentionally small and behavior-preserving: it only changes *which* `SimpleCondFn` object is handed to JAX (a memoized one), never the output of `cond`/`switch` or how NNX state updates are applied.

### Implementation

Following Flax conventions (2-space indentation, full docstring on the new helper). The PR touches exactly two files — `flax/nnx/transforms/transforms.py` and `tests/nnx/transforms_test.py`; no `CHANGELOG.md` entry was included.

**`flax/nnx/transforms/transforms.py`:**

- Added `import weakref`.
- Added a module-level cache and helper right after `SimpleCondFn`:

  ```python
  _simple_cond_fn_cache: weakref.WeakKeyDictionary = weakref.WeakKeyDictionary()


  def _get_simple_cond_fn(f: tp.Callable[..., tp.Any], graph: bool) -> SimpleCondFn:
    """Returns a cached ``SimpleCondFn`` for ``(f, graph)``.

    ``jax.lax.cond`` / ``jax.lax.switch`` key their tracing cache on the identity
    of the callables they trace. Constructing a fresh ``SimpleCondFn`` on every
    ``cond``/``switch`` call gives each branch a new identity, defeating that
    cache and forcing re-tracing (and blocking the persistent compilation cache);
    see https://github.com/google/flax/issues/5512. Reusing the same wrapper for
    a given ``(f, graph)`` keeps a stable identity so repeated calls hit the
    cache.

    ``f`` is held weakly so locally-defined branches stay collectable. Callables
    that do not support weak references fall back to a freshly constructed
    wrapper.
    """
    try:
      by_graph = _simple_cond_fn_cache.get(f)
      if by_graph is None:
        by_graph = {}
        _simple_cond_fn_cache[f] = by_graph
    except TypeError:
      return SimpleCondFn(f, graph=graph)
    wrapper = by_graph.get(graph)
    if wrapper is None:
      wrapper = SimpleCondFn(f, graph=graph)
      by_graph[graph] = wrapper
    return wrapper
  ```

- `cond` now calls `_get_simple_cond_fn(true_fun, graph)` / `_get_simple_cond_fn(false_fun, graph)` instead of constructing `SimpleCondFn(...)` inline.
- `switch` now uses `[_get_simple_cond_fn(f, graph) for f in branches]`.

#### Design decisions

- **Two-level dict (`WeakKeyDictionary[f] -> {graph: wrapper}`)** rather than a single key of `(f, graph)`. A `WeakKeyDictionary` can only weaken its *key*; `(f, graph)` tuples are not weak-referenceable and would re-introduce the leak. Keying weakly on `f` alone, with an inner plain dict over the small `bool` domain, is the structure the issue author prototyped and keeps `f` collectable.
- **`try/except TypeError` fallback** instead of pre-checking with `weakref.ref(f)`: the lookup itself is the cheapest place to discover non-weak-referenceability, and the fallback (a fresh wrapper) is exactly the pre-fix behavior, so correctness is never at risk — only the caching optimization is skipped.
- **Reused one helper for both `cond` and `switch`** to avoid divergence, since `switch` had the identical anti-pattern.
